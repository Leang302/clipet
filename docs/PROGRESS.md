**The user then ran the real app on their own interactive Mac** (this sandbox still has no display) and that surfaced real bugs, now fixed:
- Clipboard **image** capture confirmed working for real (a screenshot they copied showed up correctly in history) — the "unverified" flag on this is lifted.
- Bug: opening the editor made the history popup silently disappear, making "Done" look like it closed everything. Root cause: the history window hides itself on OS focus loss, and showing/focusing the new editor window counts as a focus loss. Fixed with an `EditorSession.active` flag the history window's blur handler checks — it no longer hides itself when the reason for the blur is our own editor taking focus, and `close_editor` now explicitly refocuses history afterward.
- Bug (reported, not yet confirmed fixed by the user): pressing Enter to paste "seems like not pasting." Most likely cause: `enigo`'s synthetic ⌘V requires macOS Accessibility permission, and `CGEventPost` fails **silently** without it — previously this meant the item still got copied to the clipboard and the UI claimed "Pasted" even though nothing visibly happened. Added an `AXIsProcessTrusted()` preflight check (Apple's own trust-check API) so this now surfaces as an explicit, actionable error ("grant access in System Settings → Privacy & Security → Accessibility…") instead of a false success. **Still needs the user to confirm this resolves it, and to actually grant the permission once prompted.**
- Per user feedback, changed paste shortcuts: Enter now pastes the whole current selection (single or multiple) — Shift is no longer required for multi-paste. Editor: Enter now saves & closes (acts as Done), matching Escape's existing cancel behavior.
- Annotation editor built: a second Tauri window (`editor`), reusing the prototype's canvas-tool logic (pen/highlighter/arrow/rect/ellipse/line/text/blur/pixelate/crop/eraser/undo/redo) but operating on real saved PNGs via `save_annotated_image`/`get_image_data_url`/`get_items`, with the original capture preserved on first edit (`<id>.original.png`), supports both single-image and batch (multi-select "Edit Selected") editing with a Prev/Next thumbnail strip, and auto-copies to the clipboard after a single-image save per spec §9.
- Per user request, "Clear" no longer wipes everything: added `clear_non_favorites` (deletes all non-favorited items and their image files, keeps favorites and their files) as the default Clear action in the sidebar, with `clear_history` (wipe-everything) kept as a separate, not-yet-exposed-in-UI "danger zone" command. Covered by a new passing unit test.
- Also fixed a real bug in the test suite itself: the temp-dir naming for DB unit tests used a timestamp that could collide across parallel test threads, causing one test to silently corrupt another's SQLite file (`most_recent_hash_tracks_latest_insert` failed intermittently with data from a different test). Switched to an atomic counter; reran the suite 5x to confirm the flakiness is gone. 6/6 tests pass.

**Next round of real-usage bugs found and fixed:**
- **UI overflow:** the bottom hint bar had a fixed 36px height but its text could wrap onto a second line once the (user-resizable) window got narrow, spilling outside the bar. Fixed: the bar and its items no longer wrap; the long trailing message truncates with an ellipsis instead.
- **"Clear" appeared to do nothing:** `window.confirm()` is unreliable inside Tauri's webview — it can silently no-op instead of showing a dialog, which was almost certainly why nothing happened. Replaced it (and the editor's "discard unsaved edits?" confirm, and its `window.prompt()`-based text tool) with real in-app modal UI that doesn't depend on the webview's native dialog support.
- **Ctrl/Cmd+A didn't work in the search box:** the global "select all items" shortcut was intercepting it even while typing in search, blocking the browser's normal "select all text in this field" behavior. Now scoped to only fire when the search field isn't focused.
- **Selection order was wrong:** multi-selecting with Ctrl/Cmd-click (as opposed to Shift-range) adds to a JS `Set` in click order, which doesn't necessarily match the list's display order — and that order was leaking into the preview stack, "Edit Selected" batch order, and multi-paste order. Fixed by always deriving the ordered selection from the current visible list's position, per spec §6 ("Default to history-display order for batch operations... Never silently reorder screenshots during transfer").
- **Popup rounded corners:** since it's a borderless window, there's no native rounding to fall back on. Made the `history` window `transparent: true` and gave `#clip-popup` its own `border-radius` + background. **The first attempt didn't work** (user confirmed still square): on macOS, Tauri silently ignores `transparent: true` unless `app.macOSPrivateApi: true` is set in `tauri.conf.json` *and* the `macos-private-api` Cargo feature is enabled. Both are now set. Note: "private API" means Apple App Store distribution is off the table with this setting; direct/DMG distribution is unaffected. **Still square after that** — the real culprit: both windows share one Vite bundle, so `editor.css` (loaded after `clipflow.css`) set `body { background: white }` in the popup window too, painting over the transparent corners. Fixed by tagging `<html data-window="…">` per window in `main.tsx` and scoping each stylesheet's page-level rules to its own window. Verified with headless Chromium against the built CSS: popup `html`/`body` now compute to fully transparent.
- **Editor flickered while drawing, and freehand strokes vanished on release:** every pointermove cleared the visible canvas, then `await`ed a fresh decode of the image from its data URL before redrawing — the blank gap was the flicker. Separately, pen/highlighter/eraser committed via a helper that *reset the layer before snapshotting it*, so strokes were saved blank. Rewrote the drawing loop: decoded images are cached, drags repaint in one synchronous pass, and commit snapshots exactly what's on screen. Added ⌘/Ctrl+Z undo and ⌘/Ctrl+Y (or ⌘/Ctrl+Shift+Z) redo per user request. Verified headlessly against the built app with a mocked Tauri bridge: 0 blank frames across a 15-step stroke, stroke persists after release, ⌘Z/⌘Y/Ctrl+Z all behave correctly, no JS errors.
- **Text annotations are now live objects** (user request: draggable, resizable, recolorable). Previously text was rasterized into the annotation layer on placement. Now each image's history carries a `TextObj[]` layer drawn above the raster layer and only baked into pixels by `flattenToDataUrl` on Done. Text tool: click empty space to add, click+drag to move, drag the corner handle to resize, sidebar color/size restyle the selection (consecutive tweaks collapse into one undo step), double-click to edit, Delete removes, Esc deselects. Blur/pixelate/crop operate on the image *without* the text so it stays editable (crop shifts text coordinates). Verified headlessly end-to-end (add, move, resize 18→36px, recolor, undo, delete, undo, and the saved PNG contains the text but not the blue selection UI); caught and fixed a bug where Delete was ignored while focus sat on the color picker.
- **Shapes (rect/ellipse/line/arrow) are now live objects too** (user request: draggable). Generalized the text layer into an object layer (`Obj = TextObj | ShapeObj`, per-step `objsHistory`). Added a Select (↖) tool; clicking an existing object under Select/Text/any shape tool selects it, body-drag moves, round handles move a rect/ellipse corner or a line/arrow end, sidebar Color/Thickness restyle it, a "Delete selected" button (plus Delete key) removes it; new shapes start selected. Unselected rect/ellipse outlines are grabbed by their stroke so you can still draw inside them. Pen/highlighter/eraser/blur/pixelate remain raster. Verified headlessly (draw, move, reshape, thicken, recolor, delete, undo, select+move an arrow, saved PNG has shapes but no selection UI); text and stroke tests re-run and still pass.
- **Sort dropdown overflowed into the preview panel:** the search input's default min-width (its intrinsic ~170px) plus the select exceeded the 300px list panel. Fixed with `min-width: 0` on the input / `flex-shrink: 0` on the select; verified the select now ends inside the panel even with its longest option.
- **Paste did nothing (user report), two root causes found by tracing the code:** (1) opening the popup makes the app active, and paste only hid the *window* — the app stayed active with no window, so the synthesized ⌘V landed in Clipet itself. Fixed by hiding the *app* (`AppHandle::hide`, i.e. `NSApp hide`) and restoring the captured frontmost process; the popup toggle now unhides the app first. (2) The Accessibility check ran after the popup hid, so its error appeared in an invisible window. The permission preflight now runs before any clipboard mutation or focus change; failure shows a readable 9s message, and `AXIsProcessTrustedWithOptions` triggers macOS's own prompt with a link to settings. Dev-mode gotcha: under `npm run tauri dev`, macOS attributes Accessibility permission to the launching terminal (e.g. VS Code), not to the app. **Still unverified on a real screen.**
- **Accessibility showed Clipet as enabled but paste was still blocked (user report):** the live process was the packaged `/Applications/Clipet.app`, not a VS Code dev process. The installed bundle had no valid full-bundle signature; only its Mach-O slices carried linker-generated ad-hoc identities, so replacing the build left a stale enabled-looking TCC row while `AXIsProcessTrusted()` correctly returned false. Added `npm run tauri:build:mac`, which auto-selects a Developer ID/Apple Development identity and refuses to emit an unsigned macOS bundle; built and verified a signed universal app/DMG, installed it with the unsigned app preserved as `/Applications/Clipet-unsigned-backup.app`, and reset only `com.clipflow.app`'s stale Accessibility record. Permission-denied paste now stages a single item/native image batch for manual ⌘V and shows a persistent recovery dialog with exact packaged-vs-dev guidance, Open Accessibility, and Try Again actions. The final macOS enable toggle and real target-app paste still require interactive user confirmation.
- **Intermittent multi-image loss and slow text paste (user report):** the old batch path replaced the one system clipboard every 350ms, so destinations that read/decode images asynchronously could miss earlier images; every single paste also waited a fixed 180ms before sending ⌘V. All-image selections now preflight every complete PNG and publish one ordered native batch with one paste event. On macOS each item carries both exact PNG data and a file URL; other platforms use a verified native file list. Text paste now captures/reactivates the prior app and proceeds as soon as macOS confirms it is frontmost. Paste work runs off the UI thread, backend/frontend guards prevent overlapping sessions, held Enter is ignored, and mutations that could remove an in-flight image are disabled in the UI. Rust paste/preflight tests and frontend/Rust builds pass; third-party target acceptance still needs an interactive compatibility pass.
- **Clipet crashed on every paste (user report: "the app keeps closing"):** the macOS crash reports (`~/Library/Logs/DiagnosticReports/app-*.ips`, `EXC_BREAKPOINT` in `TSMGetInputSourceProperty → dispatch_assert_queue_fail`) showed that moving paste work onto a `spawn_blocking` worker broke the keystroke step. enigo resolves `Key::Unicode('v')` through the Text Input Sources API, and macOS aborts the process when that is called off the main thread. `synth_paste_keystroke` now runs the keystroke on the main thread via `run_on_main_thread` and waits for the result. Clipboard prep and the focus handoff stay on the worker. Builds clean and all Rust tests pass. **Still needs a real paste on the user's Mac to confirm.**
- **Renamed to Clipet** (user request) with the user-supplied cat SVG as the app/tray icon (`app/icon-src/clipet.svg` → 1024px PNG → `tauri icon`). Bundle identifier deliberately left as `com.clipflow.app` so existing history (stored under that identifier's app-data dir) carries over.
- **Editor opened underneath the popup, and click-outside stopped closing it:** the popup is always-on-top, so the editor appeared behind it, and an earlier "don't hide while editing" guard blocked click-outside-to-close. Replaced with: opening the editor hides the popup; `close_editor` brings it back with selection intact (spec §10). The editor's OS close button now goes through the same Cancel flow (discard-confirm if dirty, then restore the popup) instead of just hiding the window.
- **Theme is now manually adjustable, not just system-driven:** added a Light/Dark/System selector in the sidebar (`src/theme.ts`), persisted to `localStorage` and synced live to the editor window (which is a separate document/webview) via the `storage` event.

**Smart Snippets / text expander, Phase 1 (user spec, 2026-11-04):**
- Type `;keyword` and then Space (default), Tab, or either. Clipet erases the shortcut and inserts the saved text. With Space it adds one trailing space; with Tab it consumes the Tab. Unknown shortcuts, and shortcuts inside a word (`abc;name`), pass through untouched.
- Escaping: `;;text` becomes `;text`, even when `text` is not a registered shortcut, and it never expands. Only one prefix is removed. It can be turned off in settings, which leaves `;;text` literal.
- Pausing: from the tray (one-click pause for the default 15 minutes, or 5/15/30/60 minutes, until resumed, or resume), or from the Snippets view's status bar. The deadline uses wall-clock time, so a pause that ends while the Mac sleeps is already over on wake. A timer thread updates the tray. Pause state persists across restarts. While paused, there is no expansion, no escaping, and no word tracking, and any word in progress is forgotten on pause and on resume.
- Snippets view (✂️ in the sidebar): list, search, create, edit, delete with confirmation, duplicate (the copy starts disabled), enable/disable, copy, paste, usage counts, a live duplicate-shortcut warning (also enforced by a unique index), keyboard navigation (↑↓, Enter to paste, ⌘N new, ⌘↵ save, Esc). You can create a snippet from history by right-clicking an item and choosing **Create Snippet…**, or with the **✂️ Snippet** button. Snippet settings: enable, trigger key, prefix, double-prefix escape, case sensitivity, default pause length.
- **Storage is independent of history:** snippets and their settings live in their own `snippets.sqlite3` with a versioned migration (`PRAGMA user_version`). No clear, cache or temp-data action opens that file. A regression test wipes the history database and the `images/` cache and checks that snippets survive.
- **macOS engine** ([snippets/macos.rs](../app/src-tauri/src/snippets/macos.rs)): a filtering session `CGEventTap` on its own thread, which needs the Accessibility permission paste already uses. It retries every 3s until permission is granted, so no restart is needed. It tracks only the current word and logs nothing. Our own injected events are marked, so there is no recursion. Keystrokes typed during a replacement are held and replayed in order. Injection runs on the main thread (the same thread-safety lesson as the paste crash). Short single-line text is typed. Multiline, long or tab-containing text is pasted, and the previous clipboard (all representations) is restored 600ms later unless something else changed it; that paste is kept out of history. Expansion is skipped when secure input is on (password fields), when a Korean/Japanese/Chinese IME input mode is active, when focus moved to another app, and inside Clipet itself.
- Verified: 25 new Rust unit tests (engine: Space/Tab/Both, unknown, inside-word, escape incl. unregistered/disabled/`;;;x`, Backspace into unknown text, navigation reset, no double expansion, case sensitivity, non-ASCII, long words, multiline, custom prefix, validation; store: CRUD across reopen, case-insensitive uniqueness, history/cache wipe, settings/pause roundtrip, migration idempotence). Full suite 38/38, `tsc` + `vite build` clean. A dev-binary launch confirmed that startup works and that the listener correctly reports `NeedsPermission` when not trusted. **Real typing in real apps has not been tested yet.** It needs the signed build installed with Accessibility enabled.
- **First real-use fixes (user report: "only works after I close the popup, second time it doesn't"):** The diagnostic log (`~/Library/Logs/com.clipflow.app/snippets.log`, which records decisions only, never typed text) showed `;name` being refused after the user Backspaced over a previous expansion. The engine didn't count inserted text as known, so deleting it looked like deleting into unseen text, and that blocked expansion until a click. The engine now tracks known text left of the caret, including what it inserted (in memory only, at most 256 chars, cleared on click, navigation or app switch). It still blocks only when Backspace goes past everything it has seen. Also fixed: tray status updates no longer block the listener thread (macOS had measured about 22s average tap latency), and the frontmost-app check that could skip every expansion is now diagnostic only. 42/42 tests pass. Real use confirmed expansion fires (use count 3) before this fix; retyping after deleting is covered by new tests.
- Known Phase 1 limits: shortcuts must be ASCII (`A–Z 0–9 - _ .`), and words containing non-ASCII characters are never rewritten, because erasing combining characters (Khmer, Hangul) with Backspace isn't exact across apps. Snippet content itself can be any Unicode. Undo is app-dependent: typed insertions usually undo in one or two steps, and pasted ones in one. A click into the middle of existing text can't be detected as "inside a word". There is no Windows hook yet; the listener reports "unsupported" there. Not done yet: the global toggle shortcut (Phase 2, with the other configurable shortcuts), categories, picker, import/export, dynamic variables, templates, and per-app rules.

**Desktop UX, editor and OCR pass (user spec, 2026-11-04).** The two screenshots referenced in the spec were not received, so this pass worked from the code.
- **Browser-style selection (root causes verified in code):** no `user-select` rule existed anywhere, and Shift/⌘-click on history items also extended the webview's native text selection. Fixes: the popup and editor are `user-select: none`, with inputs, textareas and intentional content (`.selectable`: text, link and OCR previews, snippet content) left selectable. Images are non-draggable, and modifier-clicks call `preventDefault` on mousedown.
- **History selection and keyboard:** selected items get a fill; the keyboard cursor gets an inner ring; multi-selection shows check marks. Escape peels back in layers: search text, then a multi-selection, then the popup. ⌘A selects all items in the list and the text in the search box. Delete/⌫ removes the selection, confirming when there's more than one. Clicking empty list space clears a multi-selection. Items hidden by a filter or search leave the selection. The preview header shows type and age, or "in paste order" for multiple items.
- **Clear now also keeps pinned items.** It used to delete pinned non-favorites. Deleting or clearing now also removes each item's preserved original and thumbnail, which used to be leaked on single delete.
- **Editor:** rectangles and ellipses get four square corner handles; lines and arrows keep round endpoint handles. The selected object takes hit priority over objects stacked above it. The properties panel shows the selection's own values, or the current tool's defaults when nothing is selected (selecting no longer overwrites tool defaults), and only the properties that apply. Zoom: Fit, 100% (one image pixel per device pixel, HiDPI-aware), ⌘+/⌘−/⌘0/⌘1, pinch. Hold Space and drag to pan, and edges stay reachable when zoomed. **Bug fixed:** undoing a crop used to stretch the image, because the canvas kept the cropped size. The canvas size now comes from each history step's image. Saves are write-then-rename and update the stored pixel hash.
- **OCR search:** [ocr/](../app/src-tauri/src/ocr/) uses Apple Vision (on-device) on macOS and Windows.Media.Ocr on Windows, with no network or keys. One background worker processes images newest-first with a 250ms pause between them. Status lives in `clip_items.ocr_status/ocr_text/ocr_lines` (additive migration), so existing history is indexed and a restart resumes. An image interrupted mid-OCR is marked failed rather than retried, to prevent crash loops. Results for deleted items are dropped. Editing re-queues the image. Search covers content and OCR text together. OCR-only matches show a "text in image" tag, matching lines are highlighted on the preview image, and "Text in image" can be expanded and copied. There's a sidebar toggle with progress. Repeat copies of an existing image move it to the top instead of storing and OCR-ing a duplicate.
- **Thumbnails:** the list now uses cached 160px thumbnails (`<id>.thumb.png`, regenerated when the source is newer). Full images load only for previewed items.
- **Verified:** 49/49 Rust tests, including real Vision OCR of a rendered "NullPointerException" image and a blank image. A new `npm run test:ui` (Playwright, mocked Tauri bridge, real built bundle) passes 37/37 checks covering drag/Shift/⌘-click selection, ⌘A, Escape layering, OCR search, highlight, thumbnails, multi-delete, clear text, editor corner resize, endpoint drag, property scoping, deselection, crop undo, HiDPI 100% zoom and pointer accuracy when zoomed. The installed app OCR'd all 8 existing images in about 20s. The Windows build cross-compiles, but **Windows OCR has never run.** It needs an OCR language pack matching a Windows profile language; failures show as "Couldn't read text" and can be retried.
- **Not changed and still open:** the Screenshots category stays empty because nothing captures screenshots natively yet. OS screenshots copied to the clipboard arrive as ordinary images, and macOS doesn't mark them as screenshots. Khmer isn't among Vision's OCR languages.

**OCR accuracy, Korean and search pass (user spec, 2026-11-04).** This audit came first and measured everything; no claims below are unmeasured.
- **Audit (before):** Apple Vision in Accurate mode with language auto-detect and language correction, run on the original full-resolution file (never the thumbnail), after annotation too. Text was stored complete and in NFC. Search was a JS `includes` substring match, which already handles Korean substrings like 매출 inside 매출관리내역. On the user's real 2460×1318 Korean business screenshot it found 53/53 reference phrases. The visible errors were cropped-edge characters, which are in the image itself, and ⇅ sort icons read as "1", "기" or "11".
- **Benchmark** (`cargo test --release ocr_benchmark -- --ignored --nocapture`, [ocr/bench.rs](../app/src-tauri/src/ocr/bench.rs)): 31 synthetic images at 9–24px, light and dark, low-res, Korean, English and mixed (including mostly-English stack traces), plus the user's 2 real screenshots via `CLIPET_OCR_BENCH`. Synthetic phrase recall: v1 97.7% (96.6% exact) → **v2 100% (100% exact)**. Real: 100% → 100%. Fast mode (15%) and English-only (17%) can't read Korean. Turning language correction off lost "API플랫폼". Grayscale/contrast preprocessing gave no gain, so it isn't used. Production v2 = Korean+English languages, correction on, 2× in-memory upscale for images under 1600px. Cost: 0.9s cold and about 0.4s warm for the large screenshot, 30ms for a small crop, about 120MB peak for the test process.
- **Known engine behavior:** Vision can insert a space inside long Latin words ("Null PointerException"). Search therefore also matches OCR text with spaces ignored. OCR text is never edited.
- **Search** ([search.ts](../app/src/search.ts)): NFC normalization and case-insensitive matching. Space-insensitive matching against OCR text. Multi-word queries match when every word appears in content or OCR. Ranking is exact, then substring, then space-insensitive, then all-words, with the chosen sort applied within each rank.
- **Versioned re-scans:** `clip_items.ocr_version` (current 2) and `ocr_error` (additive migration). Older results are re-scanned in the background after new images, and old text stays searchable until replaced. A re-scan is stamped first, so it can't crash-loop. Changing the language re-queues everything. Re-scanning one image (panel button or right-click, selection-aware) jumps the queue. Verified: all 11 real images were upgraded within 25s of installing.
- **UI:** the "Text in image" panel opens itself when the search matched text inside the image. It shows a line count, all text (scrollable, selectable), Copy text and Re-scan, a short status badge (reading / re-scanning / no text / couldn't read), and the stored error in plain language. The sidebar adds a language picker (Korean + English default, Automatic, English, Korean) and "Improving N images…" progress. There's no accuracy setting: the only alternative engine mode can't read Korean.
- **Windows:** the language maps to a Windows OCR engine (Korean + English uses the Korean engine if its pack is installed, otherwise the profile languages; Korean-only without the pack shows how to install it). It cross-compiles but has never run. In-memory preprocessing is macOS-only.
- **Tests:** 51 Rust tests (new: real-Vision Korean/English UI text in light and dark, versioned re-scan queue). `npm run test:ui` passes 51/51 (new: 매출관리내역, 매출, 관리, 내역, NFD query, case- and space-insensitive English, mixed query, exact-first ranking, no duplicates, auto-expanded panel, highlight, error message, Re-scan).

**Image snippets (user request, 2026-11-05).** A snippet can now be an image: typing its shortcut (e.g. `;logo` + Space/Tab) erases the shortcut and pastes the image.

Each snippet owns its copy: creating copies the history PNG, duplicating copies the file, deleting or replacing removes it.
- **Expansion (macOS):** the engine returns `Decision::ExpandImage` (no text inserted, line tracking reset). The worker reads and decodes the PNG off the main thread; a missing/damaged file skips the expansion and leaves the typed text. The main thread stages the PNG on the pasteboard, marks it as a self-write using the hash the history monitor would read back, erases the shortcut, sends ⌘V, and restores the previous clipboard after 1.5 s (text uses 600 ms).

## Key decisions (made independently, per spec §21 step 1)

- **Stack:** Tauri 2 + React + TypeScript (frontend) + Rust (backend/native layer). Confirmed viable for clipboard monitoring, global shortcuts, tray/menu bar, and local SQLite storage. Screenshot capture and OS-native multi-format clipboard writes will need platform-specific Rust code (not pure web APIs) — see Architecture doc §"Native gaps".
- **Storage:** SQLite (via `rusqlite` or `sqlx`) for history metadata + managed files directory for image binaries/thumbnails, per spec §17.
- **MVP scope vs later:** OCR search, encrypted history storage, and cloud sync are explicitly out of MVP (spec allows this — §12 OCR is "optional", §16 encryption is "consider", §16 cloud is "not required for first release").
- **Multi-image paste (spec §11):** all-image selections now ship as one ordered native payload and one paste event. macOS exposes both PNG and file-URL representations per item; other platforms use the native file-list representation. Mixed selections retain sequential transfer with preflight and payload-aware pacing. Export/combine/contact-sheet is the next explicit fallback, and real-app compatibility is tracked rather than inferred from clipboard format support.
- **No main window on launch** — tray/menu bar only, per spec §3. Expanded history window explicitly deferred (spec allows only "if explicitly requested").

## Blockers

- **Windows testing is categorically unavailable in this environment.** All Windows-path code will be written against documented Win32/Tauri APIs but marked "unverified on Windows" until someone runs it there.
- **No interactive GUI/display session in this shell.** This sandbox can build and run the compiled binary as a background process and prove things through logs/DB/CLI side effects (as done for clipboard text monitoring), but cannot click tray menus, see the Dock, grant Screen Recording permission, or visually inspect windows. Everything GUI-interactive needs a pass on a real interactive Mac session before being called verified.
- **Public distribution signing / notarization:** an Apple Development identity is available and now signs local test builds, but no Developer ID Application/notarization credentials are configured for distributable releases or CI.
- **Real third-party app compatibility testing for multi-image paste** (spec §11 success criteria) requires manually testing against apps like Word, Slack, Photoshop, Finder, Explorer — will be done incrementally as those integrations are built, documented in a compatibility matrix, not assumed.
